# Asset production and acceptance
The current milestone uses the existing rig, materials, weapons and seven clips. The local pilot adds Death, a playable controller and a contact-tested practice dummy. No paid generation is proposed.

| Phase | Next executable gate | Credit ceiling |
|---|---|---:|
| 0 Warrior pilot | Port Death to R55 with zero change to existing joint transforms. Retest shield, sword, grounded feet, guard clearance and recovery in the real game. Compare at production camera distance. | 120 |
| 1 Heroes | After pilot visual acceptance, complete Warrior and Mage movement, combat, equipment and 13-clip libraries. | 600 |
| 2 Enemies | Use the pilot dummy to verify hit timing. Add a skinned enemy, attack, hurtbox and death before expanding the roster. | 500 |
| 3 City | Place the inspected nine-step gateway in a reversible scene with traversal and camera-occlusion tests. | 200 |
| 4 VFX | Bind a local slash arc to confirmed strike timing. Measure effect lifetime and frame cost. | 120 |
| 5 UI | Validate the reference HUD in a complete R55 checkout. Review scaling, numeric readouts, and the differences in the flask and skill banks. | 40 |
| 6 Icons | Inventory the existing atlases before authoring additional missing icons. | 70 |

Local Blender and Godot can handle these immediate gates. Accept a model when all intended clips respond to input, weapon attachments remain stable, contacts are credible and the visual comparison meets the approved art. Reject regression in inherited animations, visible guard/body penetration, broken deformation, or unconvincing silhouette. The ceilings are planning figures.
