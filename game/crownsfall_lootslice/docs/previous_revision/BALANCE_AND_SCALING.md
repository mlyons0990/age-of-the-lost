# Gear, stats and balance workbook

Status: formulas are implemented in this isolated prototype. Values are starting balance choices, not final campaign tuning. data/balance_snapshot.csv is generated by tests/export_data.gd; edit the source formulas and regenerate rather than hand-editing results.

## Six primary attributes

For level L, let n = L − 1. Gear attributes add after the class's level growth. This is the Warrior baseline; the twelve unimplemented classes need their own validated growth profiles.

| Attribute | Warrior base and growth | Current effect |
|---|---|---|
| Strength S | 10 + 2n | +0.8% additive weapon-power multiplier per point |
| Dexterity D | 8 + n | +0.15 percentage points crit chance per point |
| Vitality V | 10 + 2n | +4 maximum life per point |
| Intelligence I | 6 + n | +2 mana and +0.6% recovered-spell multiplier per point |
| Wisdom W | 7 + n | +1 mana, +0.12 mana/s per point |
| Charisma C | 5 + floor(n/2) | Tracked and displayed; no combat/vendor effect yet |

Charisma’s future reputation/dialogue role should not secretly inflate item prices in the current branch. Attack speed, stamina, elemental resistances and Renown are inherited long-term requirements but are not implemented here. The derived spell-power value is used by recovered magic; it is not a second independently rolled item stat yet.

## Derived formulas, exact current behavior

Let gear.damage, gear.armor, gear.hp and gear.crit be sums over equipped items only. Strength etc. already include equipment contributions. Let chosen modifiers be HP%, Armor%, Damage%, CritFlat and CooldownReduction. Selected level-40 training can provide modifiers; no base-class passive grants them automatically.

```
max_hp = round((60 + 12n + 4V + gear.hp) × (1 + HP%))
max_mp = round(30 + 3n + 2I + W)
weapon_power = (10 + 3n + gear.damage) × (1 + 0.008S + Damage%)
spell_power = weapon_power × (1 + 0.006I)
armor = (5 + 2L + gear.armor) × (1 + Armor%)
crit_chance = clamp(0.03 + 0.0015D + gear.crit + CritFlat, 0, 0.60)
mana_regen_per_second = 2 + 0.12W
incoming_reduction = armor / (armor + 40 + 12 × attacker_level)
```

At level 1 with no equipment: 100 life, 49 mana, 10.8 weapon power, 11.1888 spell power, 7 armor, 4.2% crit and 2.84 mana/s. A weapon with exactly +10 damage gives 21.6 weapon power. These values are checked in Godot.

A normal direct hit uses the ability coefficient times the appropriate power, then random variance 0.9–1.1. Rallying Cry multiplies damage by 1.3 while active. A critical direct hit multiplies by 1.75. The model applies player armor only to incoming enemy attacks; enemies do not yet have armor/resistances. Expected direct damage before mitigation is approximately base × (1 + 0.75 × crit chance), because uniform ±10% variance has mean 1.0. That is an expectation, not a promise for any one hit.

Burn applies for 3 seconds, ticks at 0.5s and keeps the strongest active burn DPS. Current burn DPS = burn coefficient × weapon_power × chosen burn multiplier / 3. Burn cannot crit and does not apply a fresh crit roll each tick. Recovered cone direct damage uses spell power, but its burn still uses weapon power in the inherited damage handler; this asymmetry is a known follow-up, not an undocumented second spell multiplier.

Armor exhibits diminishing returns against a fixed attacker level. At 52 armor versus a level-1 attacker, reduction is 50%; at 104, it is 66.7%. Character-sheet armor is not itself “percent damage reduction.” A future resistance sheet needs separate damage schools and caps with explicit combat logs.

Cooldown = base cooldown × (1 − chosen cooldown reduction) except the primary slot currently uses base cooldown. No current selectable modifier grants CDR, but the legacy special case remains; normalize this when adding cooldown gear. Cooldowns are runtime state and do not survive restart. Resource changes on equipment swaps clamp to the new maximum; they do not refill life or mana. Level-up deliberately refills both in this prototype.

## Item generation

A random roll chooses Common / Magic / Rare / Legendary. Multipliers are 1 / 1.25 / 1.55 / 2.0. Each item also has a uniform quality roll in 0.85–1.15. Let q = rarity multiplier × quality. Item required level is the drop level. Elite drops increase the rarity roll; this is a prototype boost, not a separately published probability table.

| Item base | Primary budget before rounding |
|---|---|
| Sword | damage = (3 + 1.6L)q |
| Chest | armor = (8 + 3L)q; life = 2Lq |
| Shield/helm/gloves/boots | armor = (4 + 1.5L)q |
| Belt | life = (4 + 3L)q |
| Ring/amulet | life = 2Lq; crit = 0.012q |

Magic and higher add one random primary attribute with amount max(1, round((1 + 0.2L)q)). This is intentionally small content coverage: there are no true prefix/suffix pools, affix tiers, crafting or rolls that change an ability. “Legendary” currently means a rarity tier with larger budgets and an Epochbound name; it does not mean that a bespoke legendary power exists.

Base sell value = round((5 + 2L) × rarity multiplier × (1 + rarity index)). Quartermaster buy price is 3× sell value. Health potions cost 5 gold and cap at five held. Do not multiply the already-rounded sell value by another rarity factor at the UI layer. Equipment comparisons use actual derived-stat differences; item_score survives only as a legacy helper and never chooses equipment or sells items.

A production affix plan should separate base defense/weapon budget, implicit modifier, prefix pool, suffix pool, required level, item power and visual rarity. Weighted affix selection must exclude incompatible or duplicated groups, record rolled values on the instance, and version the generation rules. Do not regenerate rolled values when loading a save.

## Enemy scaling

Normal enemy life = round(base HP × (1 + 0.3(L − 1))^1.35). Elites multiply life by 2.8. Enemy damage = base damage × (1 + 0.24(L − 1)), with another ×1.6 for elites. The new exponent prevents later gear from making every normal enemy trivial under linear HP growth.

Enemy templates: Hollowling 30 base life / 7 damage; Veilbound Revenant 46 / 10; Thornhide Brute 95 / 16. Their windups, ranges, movement speed and cooldowns are in game_data.gd. Bosses require authored encounter budgets; simply multiplying the brute is not a boss design.

XP required from level L = floor(60 × L^1.6), cap 60. Kill XP derives from enemy level, type and elite status. Quest completion gives 25% of the current level’s required XP. The existing six-step quest loop is a training scaffold, not a campaign XP plan.

## Reading the generated CSV

The workbook covers levels 1, 10, 20, 40 and 60 under three loadouts: no gear; a midpoint common weapon; ten midpoint rare pieces without random attributes. The third is a controlled fixture, not a prediction of an average player’s build. Columns report life, mana, power, armor, crit, regeneration, same-level incoming reduction, non-crit Cleave damage, Revenant life and a simple damage-ratio estimate of Cleave hits to kill. The ratio excludes crits, variance, burn, Rally, enemy movement, animation lock and mana waits; it is not measured time-to-kill.

Balance targets for the next combat pass: common enemies should survive roughly 2–4 intentional damaging actions in ordinary gear; elites should force several telegraph decisions; a potion should recover a meaningful mistake without making repeated damage irrelevant; mobility should not outdamage dedicated attacks merely because it hits many collision frames. Validate these against real encounters at all five checkpoints, not only the CSV.

A spreadsheet is insufficient evidence of combat feel. Record level, equipped item UIDs, ability set, target type, encounter seed, hit count, elapsed combat time, damage taken, potion count and dropped rewards. Tune one budget at a time. Keep a fixture file for every disputed result.

## Mage heroic transformation proposal: Ashen Ward → Ember Aura

Design only. The Mage class and aura runtime are not present in this project.

At level 40, a discovered mastery node can transform Ashen Ward from timed defense into a toggled aura. The active slot retains a stable variant relationship: base ability ashen_ward; variant ember_aura. Turning it on pays 10 mana; each 0.5s pulse pays 3 mana before damaging targets. Insufficient mana stops the aura before that pulse. At baseline 0.30 spell coefficient per pulse, damage per second is 0.60 spell power and upkeep is 6 mana/s. Define an explicit stop condition on death, zone load, disabling effect and respec. Do not treat it as a free automatic class passive merely because it remains active.

Choose one branch:

| Branch | Mechanic | Starting balance target | Risk to test |
|---|---|---|---|
| Cinder Bloom | +25% radius; a killed burning enemy leaves one non-stacking 1s cinder patch | Patch at 0.15 coefficient/s; cannot create another patch | Chain reactions, excessive screen coverage |
| Siphon Embers | Recover life from aura damage that actually lands on living targets | 2% of actual aura damage; cap 3% max life/s | Dummy/invulnerable targets, overkill healing, recursive proc loops |

Mutual exclusion is by mastery-node group, enforced in validation and saved by stable node IDs. Changing branch removes the old effect and reconciles the running aura. Aura damage, secondary patches, item-triggered echoes and resource refunds each carry an origin tag and proc depth. Secondary triggers cannot create the same trigger recursively.

Named build targets appear in data/unique_and_set_proposals.json: Band of Continuance, Emberwake Circlet, Riftglass Focus and the Crownless set. These have explicit triggers and caps but no implemented runtime effects or illustrated assets. A named item proposal must have a matching integration test before the UI calls it functional.
